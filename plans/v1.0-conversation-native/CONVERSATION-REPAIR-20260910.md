# 连续对话优化 · 2026-09-10

## 本轮范围和事实源

用户最新确认：产品主要面向 PC，不将手机端适配作为后续迭代或发布的验收门槛。以下已执行的窄屏检查仅保留为历史验证记录；后续资源优先投入桌面连续对话、执行状态和右侧方案/证据工作区。

面向不熟悉训练的用户，沿用 `/app` 对话主入口、同一 task/conversation ID、任务列表及右侧证据工作区。训练任务、数据、合同、Run 仍由 Workspace 持久化；消息、人工检查点及会话回合仍由 MultiAgentStore 和真实 DSH 状态共同对账。前端不产生批准或完成事实。

P0：任务绑定后强制填表；聊天被吞成字段答案；上传/批准阻塞追问；长回答误折叠；审批工具显示执行中。
P1：推荐不可执行的现成模型路径；首页连接失败无法完整重试。

## 三轮修复和验收

1. 对话入口和身份：统一 intake/task-bound 对话规范；区分普通聊天和明确控件答案。连续交流保持同一 ID，发送重试使用原 request_id。
2. 检查点衔接：用户发消息时暂缓当前根会话检查点，先确认旧回合停止，再在同一会话提交新消息。不发送 approval/answer，不取消后台训练；旧卡不能继续批准。若检查点失效、属于子会话或取消未确认，则准确拒绝并保留草稿。普通执行中的排队不声称即时介入。
3. 展示和恢复：普通回答完整显示；技术动作仍折叠；批准等待根据精确调用身份显示；连接恢复同时检查任务 API 和 AI Runtime。核验桌面与窄屏。

## 不变边界

任意外部模型仍只有发现、静态分析、计划和资源检查。现成模型试跑、动态适配训练不伪造为可执行能力；真实 Run 仍要求经过验证的 Recipe/Adapter。不可变合同、最终测试集、明确授权、隔离执行及发布门槛不降低。本轮不自动部署或 git 发布。
