# AI 自主推进的产品验收工具

产品是通用训练 Agent，测试也以目标、输入输出、操作和约束描述案例。语音、OCR、NLP、时序与排序是样本，不是测试框架或产品的类型目录。测试的起点必须包含普通用户的真实表达，不应要求用户先写好模型名、数据合同和阶段协议。

## 验收闭环

`用户目标与冻结标准 → 测试规划 → 页面观察 → 选择下一步 → 实际交互 → 保存证据 → 独立检查/评审 → 问题定位 → 最小修复 → 原案例复验 → 新反例探索`

测试规划与页面执行可以由同一个测试 Agent 推进；被测产品 Agent 不得修改测试标准或接触评判答案。事实检查和语义评审分别运行。修复后保留原失败记录，另建测试批次，不能改掉原结果。

| 部件 | 输入与职责 | 约束 |
|---|---|---|
| CaseSpec | 原始用户表达、用户知识水平、预期行为、数据来源、预算、必需操作、独立评分标准 | 开放业务目标，不用 family 路由；正式执行前冻结用例与文件摘要 |
| 测试规划器 | 从目标、已有缺陷和覆盖空白形成正常、边界与故障案例 | 输出待审核案例；不自行降低产品质量门，不擅自扩大资源/数据范围 |
| 页面执行器 | 使用 CUA 的真实可见控件、文件选择器和对话 | 不绕后台 API 操作，不强启 disabled 控件；每步重新观察，不盲点固定序列 |
| EvidenceJournal | 操作、URL、页面文本、截图、文件摘要、时间、任务/Run身份 | 证据写入独立批次；截图不等同于训练证据，摘要用于检测变化而非身份认证 |
| 确定性检查器 | 上传回执、授权版本、Run、冻结评估、试用、包与重载等实际事实 | 缺失标 incomplete；执行成功、质量通过、业务正确分别判断 |
| 语义与视觉评审 | 从独立上下文审阅对话/截图，按明确 rubric 引用证据 | 没证据留 needs_review；文字评审不能替代视觉评审，AI评分须用人工正反例校准 |
| 缺陷与回归库 | 最小复现、预期/实际、严重度、所属层、证据、修复和复验 | 同一失败沉淀为固定回归；增加新输入防止针对已见答案修补 |

## 测试从哪些维度扩展

完整清单在 [coverage.json](../../scripts/acceptance/coverage.json)，它描述目标覆盖范围，不代表已经测试。主要维度包括：

- 对话：模糊目标、术语误用、已选路线、需求改变、跨轮记忆、能先给方案却反复追问、无效轮次。
- 页面：上传与发送竞态、多个文件、编码与容器格式、新输入、媒体预览、键盘焦点、任务切换、草稿、下载与刷新。
- 视觉和表达：当前决定与历史区分、组件对齐、指标单位、失败含义、按钮可达与命中区域、PC宽度/缩放、读屏标签和对比度。
- 通用性：未知目标、非预设指标、模型/数据形态与训练路线、不同实现组织方式；同一工具协议替换对话服务。
- 质量：否定与多意图、分布外样本、上下文时效/单位/覆盖、基线、语音可懂度与人工试听、OCR关键字符；不能只看离线平均分。
- 数据和授权：划分泄漏、测试曝光、坏文件、材料提示词注入、版本漂移、一次性授权、跨任务误操作、资源预算和取消的真实效果。
- 生命周期：限流、鉴权、余额、超时、流中断、上下文过长、服务重启、重复提交、旧批准恢复、已有模型继续下载而不重训。
- 交付：许可证、私有路径/数据/密钥不导出、依赖完整性、下载校验、脱离原Run的干净隔离环境重载与相同输入回放。
- 效率：首个有用回复、整体耗时、token与实际费用、工具循环、重复问题、恢复耗时；用多次重复试验报告波动。

用业务目标、用户表达清晰度、数据形式、操作顺序、模型服务和故障位置做组合；优先成对覆盖，再让 AI 根据失败探索邻近反例。不要穷举所有组合，也不要让探索无限占用模型和训练资源。

## 当前已实现的第一版

- `scripts/acceptance/cua-page-driver.mjs`：在 CUA 内导入、接收已选 tab；提供开始对话、发送、授权文件上传、精确批准和刷新；真实截图/DOM文本追加记录。默认没有执行批准，文件必须在精确许可清单和实际目录内，动作与时间有预算。
- `scripts/acceptance/agent_acceptance.py`：独立读取证据；校验文件摘要、跨案例/重复身份、操作和外部事实、引用的语义评审；输出 passed / failed / incomplete。
- `scripts/acceptance/dialogue-judge.mjs`：接收通用 `LlmAdapter`，用全新的无工具上下文审阅真实页面对话，输出逐标准的结论、理由与原文引用。当前本地调用示例使用已授权的 Codex CLI；检查器不依赖这一厂商。
- `scripts/acceptance/cases/vague-outcome.json`：不懂模型的门店用户，从模糊需求到“下周逐日预测”的真实两轮页面案例。
- `scripts/acceptance/coverage.json`：可扩展覆盖清单和测试分层。旧 `four_scenario_dialogue_cases.json` 是历史快照，不用其当时的能力状态判断当前产品。

2026-10-06 实跑记录：`runs/acceptance/20261006-adaptive/vague-outcome/`，包含5次页面捕获、两轮用户消息、独立模型评审和证据检查结果。这个咨询子集通过；没有上传、训练、模型效果或整体验收结论。文本评审没有评价截图视觉。AI对“最小实验方案”是否充分可能评分偏宽，下一步必须用人工失败样例与更具体的可观测条件校准，不能凭这一案例宣称评分器已经可靠。

运行检查器：

```bash
python scripts/acceptance/agent_acceptance.py \
  --case scripts/acceptance/cases/vague-outcome.json \
  --evidence runs/acceptance/20261006-adaptive/vague-outcome \
  --out runs/acceptance/20261006-adaptive/vague-outcome/report.json
```

在 CUA 会话中使用页面执行器：

```js
const { PageAcceptanceDriver } = await import('/absolute/repo/scripts/acceptance/cua-page-driver.mjs');
const driver = new PageAcceptanceDriver({
  tab: selectedTab, caseId: 'vague-outcome',
  evidenceDir: '/absolute/repo/runs/acceptance/new-batch/vague-outcome',
  maxActions: 20, maxSeconds: 180
});
await driver.startConversation();
await driver.send(caseSpec.opening);
// 测试 Agent 阅读返回页面，再决定下一步；没有通用“自动点批准”循环。
await driver.capture();
```

## 如何继续建设

1. 先把现有四场景与未知排序目标的真实证据接入统一报告，保留语音/OCR质量失败、工单否定语义错误、时序57天过期上下文，补齐未完成的下载重载。失败是产品改进输入，不能当作测试不方便而删掉。
2. 增加 CaseSpec schema、冻结摘要与只增不改的批次、独立事实采集器、批准范围结构验证，以及复验差异报告。当前记录器还不能提供防篡改认证，也没有常驻调度服务。
3. 建立人工标注的对话正反例、视觉基准图与可观测的组件规则；给评分器测误判率。同一模型不同上下文仍可能有相同偏差，关键准出需人工抽查或不同评审实现。
4. 让规划器读覆盖缺口和问题库，形成新案例与合法合成材料。待范围和预算通过审核后，测试 Agent 自适应执行；新目标不要求新增训练类型分支。
5. 提交时跑确定性协议/组件测试；本地冒烟跑短对话与上传；发布前跑完整训练/质量/交付、故障恢复、服务替换和PC视觉；探索批次使用独立预算并输出可复现问题。

发布准出不能合成一个平均“AI评分”。必须同时看到：必需流程证据齐全、关键不变量通过、当前业务质量结论、交互/视觉复核、已知限制与未解决问题。受控阻断可以证明错误处理正确，不能证明该任务训练完成。
