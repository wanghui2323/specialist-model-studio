# Model Harness 视觉与交互收敛稿

状态：供 v0.6 需求确认使用，不代表产品运行时已经实现。

## 1. 设计结论

Model Harness 不是“聊天框套训练表单”，也不是把 Codex、WorkBuddy 和平台产品 1 的界面拼接在一起。它采用同一套任务事实模型：

- 左侧管理 `Training Task`：创建、切换、恢复和并行查看任务。
- 中间承载 `Agent Thread`：用户输入、计划、工具事件、批准请求和阶段结论。
- 右侧呈现 `Task Context`：数据、模型、运行、评测和产物。
- 后端事件是界面的唯一进度来源；没有事件，就不显示“正在执行”或“已完成”。

## 2. 三套参考各自负责什么

### 平台产品 1：视觉纪律

- 浅灰画布、白色工作面、细描边、弱阴影。
- 普通容器 4–8px 圆角，不使用大面积渐变和营销式大卡片。
- 紫色只标记品牌、焦点和主操作；绿色表示成功，琥珀色表示等待或批准。
- 依靠字号、间距、分割线和表格密度形成层级。

### Codex：Agent 运行语法

- 项目下保存多个持久任务线程，可以切换、恢复和并行运行。
- 一次用户请求拆成有生命周期的消息、工具、批准和产物事件。
- 高风险操作进入明确的批准状态，任务暂停，批准或拒绝后继续。
- 在同一线程中查看过程、结论和可审查结果，避免跳转到多个后台页面。

### WorkBuddy：普通用户的任务可理解性

- 用一句自然语言创建任务，左侧立即出现任务对象。
- 中间持续解释当前正在做什么，而不是输出伪造的多轮动画。
- 右侧直接展示文件、变化、预览和最终交付物。
- 用户可以补充上下文、继续追问或同时创建其他任务。

## 3. Model Harness 自己的产品结构

```text
Training Project
└── Training Task
    ├── Agent Thread
    │   ├── Turn
    │   ├── Tool Event
    │   └── Approval Request
    ├── Dataset Contract
    ├── Model Asset
    ├── Training / Eval Run
    └── Artifact
```

三栏不是视觉偏好，而是对象关系的直接表达：任务是容器，Thread 负责推进，Context 负责证明。

## 4. 页面模板

### A. 新任务页

一个任务输入框 + 工作目录/数据附件 + 场景类型。创建成功后必须先返回稳定的 `task_id`，再进入 Agent Thread。

### B. 任务工作台

- 左：项目、训练任务、任务状态。
- 中上：任务标题、运行状态、当前计划和阶段。
- 中部：对话、工具事件、批准卡和 Agent 阶段结论。
- 中下：可持续追问的输入框。
- 右：数据、模型、运行、评测、产物五类上下文。

### C. 任务结果页

默认从任务工作台右侧展开，不另造一个脱离上下文的 Dashboard。重点呈现指标对比、失败样本、最佳模型、运行清单和可下载产物。

## 5. 状态语言

| 状态 | 文案示例 | 视觉 |
| --- | --- | --- |
| 未开始 | 等待数据、等待配置 | 中性灰 |
| 运行中 | 训练中 · event 42 / 67 | 紫色进度 + 绿色在线点 |
| 等待用户 | 需要批准 · 任务已暂停 | 琥珀色 |
| 成功 | 评测完成 · 0.908 | 绿色 |
| 失败 | 运行失败 · 查看原因 | 红色 |
| 已拒绝 | 已拒绝 · 未创建新 run | 中性灰 + 可追溯记录 |

禁止只靠转圈或延时动画宣称进度。每一个状态都必须能回到 `task_id`、`run_id`、事件序号或批准记录。

## 6. 视觉 Token

- Canvas: `#F5F6F8`
- Surface: `#FFFFFF`
- Surface muted: `#F8F9FB`
- Ink: `#191E31`
- Text: `#40475C`
- Muted: `#747B8F`
- Border: `#E2E6ED`
- Brand: `#6258F4`
- Success: `#1F9D63`
- Warning: `#B87514`
- Radius: `4 / 6 / 8 / 10px`
- Motion: `120 / 180 / 280ms`

品牌图形采用扁平的“H + 中心节点”，表达 Harness 对数据、模型和运行的连接。图形只使用品牌紫与运行绿，不使用立体方块、复杂渐变和通用 AI 星光符号。

## 7. v0.6 前端验收

1. 1440×900 首屏能同时看到任务、执行过程和训练上下文。
2. 左侧切换任务会更新中间任务标题，不产生假的后台状态。
3. 右侧五个上下文页签可切换并保持同一任务语境。
4. 批准卡明确说明影响、资源和暂停状态；拒绝不能创建新 run。
5. 所有模拟数据标注为原型数据，正式产品接入后替换为后端事件。
6. Logo、图标、颜色、圆角和状态使用统一 Token，不出现临时 emoji 图标。
