# Model Harness v0.7 本地可用 Beta 需求合同

> 状态：L0「事实重置」已于 2026-08-22 获用户验收；L1 已获授权启动。  
> 启动日期：2026-08-21  
> 开发分支：`codex/v0.7-real-training-beta`  
> 主对象：`Training Task`  
> 当前发布边界：本地、单用户、Alpha 基线；未合并 `main`，未发布 Beta。

## 1. 产品目标

Model Harness 面向不具备专业模型训练能力的 AI 产品经理和独立开发者。用户用业务语言描述目标并提供数据，系统负责推进到一个可验证、可试跑、可交付的本地专用模型；用户只在任务理解、数据授权、验收门槛、模型下载、启动训练、注册新能力和交付等关键节点做决定。

v0.7 不承诺“所有模型现在都能训练”。“通用”被严格定义为：

1. 已验证能力可以立即进入真实训练；
2. 可扩展能力可以在产品内完成 `Build → Test → Register → Resume`；
3. 超出安全或资源边界的能力必须明确说明原因，不得伪装成已支持。

## 3. 能力分层合同

| 层级 | 用户文案 | 允许动作 | 禁止动作 |
|---|---|---|---|
| `ready` | 已验证，可直接训练 | 导入正式数据、冻结合同、启动 Run | 隐藏版本、许可和资源限制 |
| `buildable` | 需要补齐训练能力 | 上传隔离样例、创建 Build Job、审查依赖与注册 | 创建训练 Run、宣称已支持、要求用户处理代码 ZIP |
| `unsupported` | 当前环境暂不支持 | 保存任务与工程需求、解释阻断条件 | 播放训练事件、生成成功提示、模糊承诺耗时 |

能力状态必须由后端注册表、验证报告和本机资源共同推导，前端关键词只能作为候选提示，不能成为事实源。

## 4. 目标对象与事实源

| 对象 | 作用 | 稳定身份与版本规则 |
|---|---|---|
| `TrainingTask` | 用户可恢复的主对象 | `task_id` 永不因澄清、构建或重训改变 |
| `TaskSpecRevision` | 业务目标、输入输出、设备、延迟、体积和指标 | 用户确认后形成不可变版本 |
| `CapabilityDecision` | 候选训练方案、理由、置信度和用户纠错 | 关联规格版本 |
| `StagedDataAsset` | 无 Recipe 时也能保存的隔离样例 | 通用安全体检后才能交给构建任务 |
| `DatasetVersion` | 经已验证数据读取器导入的正式数据 | 指纹不可变；替换数据产生新版本 |
| `RecipeBuildRequest / BuildAttempt` | 新能力的构建、测试、失败和重试 | 每次 Attempt 独立、可恢复、可审计 |
| `RecipeVersion / AdapterVersion` | 可执行训练能力 | 只有验证通过且带摘要的版本可以注册 |
| `ModelAsset` | HF 或本地模型资产 | 固定 repository、revision、许可、文件哈希和缓存 |
| `TrainingContract` | 数据、Recipe、模型、门槛与资源的冻结快照 | 任一依赖变化都会使旧合同失效 |
| `Run` | 一次真实训练执行 | 运行完成不等于评测通过 |
| `EvaluationReport` | 指标、样本充分性、门槛、失败样本 | `passed / failed / insufficient_evidence` 分离 |
| `InferenceCheck / ArtifactBundle` | 新样本试跑和模型交付 | 关联 Run、模型哈希与环境清单 |

后端是唯一事实源。前端、CLI 与 DeepSeek Harness Adapter 只能调用同一命令 API，不能各自维护状态。

## 5. 目标用户旅程

```text
一句业务目标
→ 创建稳定 task_id
→ 展示并确认任务理解卡
→ 判断 ready / buildable / unsupported
→ 上传正式数据或隔离样例
→ 匹配或构建训练方案
→ 冻结数据、模型与验收合同
→ 批准真实训练
→ 查看真实工具、耗时、日志和资源
→ 判断 passed / failed / insufficient_evidence
→ 上传新样本试跑
→ 下载可追溯交付包或开启下一轮
```

无 Recipe 分支必须完整实现：

```text
能力扩展请求
→ 隔离样例
→ Build Job
→ Code Agent 实现
→ 沙箱安装与测试
→ 安全、许可、正反例和深度制品验证
→ 人工批准注册
→ 回到原 task_id
→ 继续数据、合同、训练和评测
```

## 6. 产品交互合同

### 桌面端

- 左侧只负责找回任务，并显示任务状态与唯一下一步；
- 中央负责对话、计划、真实工具执行、问题、审批和恢复；
- 右侧只负责当前对象的模型、数据、训练、评测和产物证据；
- 顶部和右侧不得重复两套互相冲突的阶段；
- 每张工具卡显示输入对象、版本、原因、真实耗时、结果摘要、日志入口和事件 ID。

### 移动端

- 使用任务抽屉和 `对话 / 上下文 / 结果` 底部入口；
- Context 不得排在完整对话之后；
- 当前步骤收敛成单行状态，可展开查看完整计划；
- 主要点击区域不小于 44×44px。

### 用户术语

- Recipe → 训练方案；
- Data Adapter → 数据读取器；
- Agent Runtime → 智能协作服务；
- Artifact → 模型交付包；
- DeepSeek Harness 只出现在架构和开发文档中。

## 8. 已确认的产品决策

1. 版本定位为“v0.7 本地可用 Beta”，不使用“任意模型均可训练”的承诺；
2. 第一个动态扩展场景使用当前语音关键词识别任务；
3. DeepSeek Harness 作为内部 Agent Runtime Adapter，不作为用户产品；
4. Recipe 生成代码必须进入安全隔离环境；没有隔离能力就停止，不回退到宿主 Python；
5. v0.7 验收覆盖图片分类、表格回归和语音关键词三个真实训练家族；
6. Hugging Face 作为受控模型资产入口，不替代 Training Task、Recipe 和 Run 事实源；
7. 每轮用户验收后才提交并推送开发分支；L5 通过后才合并、Tag 和 Release。

## 9. 状态与证据规则

任务状态统一为：

`planned → implementing → implemented → verified → accepted`

- `implemented`：代码已写，但不代表运行通过；
- `verified`：自动检查和真实浏览器/运行证据通过；
- `accepted`：用户确认本轮结果；
- 只有 `accepted` 可以在用户界面显示“已完成”；
- 阻断不覆盖生命周期状态；使用独立 `blocked_by` 字段记录阻断条件、恢复动作和最后证据。

每个 Loop 必须保存：起始 URL、对象 ID、刷新结果、列表重入结果、下游证据、一个拒绝或失败结果、1440×900 与 390×844 检查、Console/Network/overflow 结果。

## 10. 全局完成门槛

- 零个未解决 P0；
- 所有 P0 流程满足对象效果、持久化、同一 ID、重入恢复、状态守卫、错误/取消六项闭环；
- 图片分类、CSV 回归、语音关键词均产生真实独立评测、模型制品和新样本推理记录；
- Recipe 与 HF 两条供应链的拒绝、失败、恶意输入和中断路径通过；
- 1440×900 与 390×844 无关键遮挡、不可达操作或假进度；
- 公开 Tag 全新克隆后能复跑最小闭环；
- 云多租户、生产发布服务和未验证模型家族仍明确标注为范围外。

## 11. 每轮执行机制

```text
冻结一个用户结果
→ 定义对象、API 和失败状态
→ 最小纵向实现
→ 单元测试与恶意负例
→ 真实数据运行
→ 刷新、重入、拒绝和恢复
→ 桌面与移动浏览器验证
→ 保存 ID、哈希、日志和截图
→ 用户确认
→ 提交推送或回退
```

L0 已验收。当前允许执行 L1「任务理解与可信控制面」；L1 验收前不进入 Recipe Factory，不训练新的语音模型。
