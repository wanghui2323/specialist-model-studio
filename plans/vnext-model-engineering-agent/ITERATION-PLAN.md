# 通用模型工程 Agent · 迭代与验收计划

日期：2026-09-11｜状态：开始增量实施，整体里程碑尚未按本计划验收；切片状态见[本轮迭代记录](CURRENT-ITERATION.md)。

目标和架构见[产品方案](PRODUCT-PROPOSAL.md)，权限与资源前置条件见[待决事项](DECISIONS.md)。规划本身不授权改变任务合同、安全边界、用户数据或发布状态；实施中的实际代码与验收结果统一记录在当前迭代文档。

## 1. 执行原则与责任分工

- 每阶段交付一条前后端联通的真实旅程；不按“所有后端→所有前端→最后测试”施工。
- 保留现有图片分类、表格回归、可信注册音频关键词分类及教学标识，不用新架构替换掉可用路径。
- 研究入口开放；执行受独立权限、隔离、资源和资格约束。临时没有环境是阻断，不是放宽安全的理由。
- 角色仅用于责任划分，不假定已有人员：产品负责人冻结业务与权限；引擎/平台研发负责执行与对象；前端研发负责 PC 交互；评测负责人维护独立协议与留出集；QA/发布负责人收集证据。
- 编码者不能独自批准权限变更、给自己的模型放行或修改测试标准。没有独立人员时必须由产品负责人承担相应审查，不能由同一 Agent 换角色文字代替独立访问控制。
- 所有新增 schema 先做当前代码、旧协议与目标的字段对照。复用现有对象，不直接照抄历史计划或发明平行 Task/Run 真值。

关键依赖：`M0 → M1 → M2 → M3 → M4 → M5`。

GPU 分支：M0 明确环境与范围 → 独立后端资格 → M2 实测设备训练/取消/资源约束 → 对应跨模态任务验证。没有这条证据链，不宣称 GPU 可用。CPU 先行是协议施工顺序，不是产品长期能力定义。

资格验证共同项：来源与环境身份、输入输出协议、合法/非法数据、独立推理、评测接口校准、制品重载、安全边界。申报训练能力必须增加最小实际训练；仅推理能力不制造训练记录，也不能获得训练资格。语法检查通过或 scaffold_ready 不计资格通过。

M2 退出：至少一个开发阶段未预装训练任务由 Agent 完成上述全链路，至少一个注入失败形成有效修复及新资格证据，J09 无训练旅程也需独立通过；不修改主干增加该任务专属分支，不由开发者临时补插件。若采用逐补丁人工审批，分别记录人工干预，不混报自主闭环。

代码编写阶段只接触训练/开发数据；评测器在独立权限域运行。必须实证“不能读终测、不能改门槛、不能伪造评测产物”，而不只检查 Agent 提示词。

| J09 | 现成模型试用→独立评测→交付 | 未创建 TrainingRun，ModelTrial 仍有精确来源/模型/环境/输入/结果身份并能交付 | 推理资格不能启动训练；缺来源或错误模型绑定不能放行；刷新重入仍关联同一试用 | M2 |

每份证据记录：commit、环境/后端版本、route、task/object ID、输入与授权摘要、用户动作、可见结果、刷新、列表重入、下游结果、负例、console/network/layout、实际质量判定。公开证据需脱敏，原始数据和运行产物不进 Git。

## 5. 通用性与专业优势的双重实验

### 5.1 覆盖矩阵：用于测试，不是支持清单

| 方向 | 必须说清的任务边界 | 合格证据（最终指标由任务合同确定） |
| --- | --- | --- |
| 图片分类 | 整图类别；不等于检测/分割 | 真实用户格式数据、类别/重要切片表现、推理与产物 |
| 表格回归 | 独立样本数值预测；不等于时序或寿命建模 | 字段与切分合理性、误差/基线、未见样本预测 |
| 实体识别 NER | 实体类型、边界、标注方式 | 标签转换正确性、实体级评测与重要类别错误 |
| 语音识别 ASR | 语言、转写/时间戳等输出约定 | 实际转写、约定错误指标、噪声/业务词等开发切片 |
| OCR | 检测/识别/版面/字段哪一层 | 对应输出的独立评测；关键业务字段；不能用纯文本识别冒充全链路 |
| 语音合成 TTS | 文本→授权声音；不默认声音克隆 | 实际音频、资源/延迟；可懂度/自然度等按已批准人工与自动协议评价 |

“图像识别”不是自动映射到分类的兜底类别，应澄清实际输出。每项都要登记来源、版本、数据合法性、资源与预算；没有这些不能冻结为可执行验收任务。

开发任务用于工程建设；留出任务在版本冻结后揭示。建议每个必选方向至少一个独立留出任务，以陌生仓库/数据结构检验迁移；M0 需先冻结哪些方向必选、每例要求推理还是训练、目标后端和任务数。仅推理验收不能计作该方向的通用训练覆盖。任务数不足时只能得出小样本可行性结论，不能宣称“所有场景已支持”。基准包含不可行负例，负例的正确阻塞单列为安全诊断指标。

### 5.2 对照组与指标

对照组为相同底模版本的通用编程 Agent：初始材料、模型/数据访问、工具执行能力、网络与隔离权限、时间、算力、上下文/尝试及人工帮助预算尽量一致，并公开差异。不能通过削弱对照组工具来证明优势。

两组还须使用相同初始权重/依赖缓存快照；记录命中、下载量、下载时间与成本，冷启动和暖启动分别报告。共享物化缓存的工程收益，与经验库改变选型/实验决策的收益分开归因。

| 指标 | 计算与防误报规则 |
| --- | --- |
| 全任务真实达标率 | 独立验收达标任务数 / 预先登记的全部任务数；阻断和失败都不计成功，不删除难例 |
| 可行任务达标率 | 另按测试前定义的可行子集报告；不能事后把失败任务改成不可行 |
| 错误放行率 | 被系统宣称达标但独立验收未过 / 系统宣称达标数；分母为零报告不可计算 |
| 时间与成本 | 从请求到首个有效结果、到达标的时间；计入模型调用、构建、训练和失败重试；超时/未达标单列，不只平均成功任务 |
| 人工介入 | 记录必要业务审批与额外技术帮助，人工写代码单列；有人工补场景代码不算自主工程完成 |
| 改进与回归 | 同初始模型、错例/标签额度和迭代预算，比较开发目标切片与独立总体结果、旧能力退化 |
| 干净环境复现率 | 成功消费/加载并按协议复验的包 / 所有声明可交付的包；哈希校验不等于可运行 |

每个结果同时记录：`达标 / 受控阻塞（原因） / 执行失败 / 质量未达标`，并附 `自主 / 人工辅助`。受控阻塞可以通过负例安全检查，但不能计作模型训练达标。

随机性任务按批准预算重复运行，报告分布和样本量；少量案例不推断统计优势。评价主体/脚本独立于工程 Agent。

### 5.3 领域收益与经验消融

- **可信改进实验**：同初始模型、开发错例、标注额度与两轮实验预算，对照目标切片改善和旧能力退化；最终测试数据只供冻结候选的独立验收。
- **经验消融**：同一 Studio 版本，比较启用与关闭经验库；来源、环境、数据、预算和初始下载缓存一致。经验库在揭示留出任务前冻结，终测内容和留出反馈不得用于该轮经验更新；不能把预下载加速算成经验决策收益。
- 建议硬门：无越权执行、无终测泄漏、无虚假成功、所有必选 P0 旅程六项齐全。M0 确认对照方法与预算，M2 开发基线后、正式优势对照/留出评测前由人冻结收益目标；具体业务质量门和回归容忍度在相应任务实验前确认。它们是新验收提案，不覆盖旧合同。

## 6. 估算与首轮安排

以下为初步工程工作量，非完成日期承诺。假设有 2 名可投入的研发，以及产品/评测/QA 审查支持；Agent 可并行协助，但不能替代运行等待、独立验收或权限决定。

| 阶段 | 初步工程人日区间 | 估算信心 | 最大不确定性 |
| --- | ---: | --- | --- |
| M0 | 2–3 | 中 | 权限、硬件和验收任务能否及时确定 |
| M1 | 10–16 | 中低 | 隔离、取消与恢复，以及现有交互耦合 |
| M2 | 16–28 | 低 | 动态工程、真实资格验证、后端和加速器兼容 |
| M3 | 10–18 | 中低 | 评测方法、样本质量和诊断收益 |
| M4 | 10–18 | 低 | 跨任务仓库差异、TTS 等评价成本、经验收益 |
| M5 | 6–10 | 中低 | 留出失败、冷安装和恢复回归 |
| 合计 | 54–93 | 初步估算 | M1 完成后必须重新估算 |

按上述人员假设、有限并行和风险缓冲，可暂按 **8–12 周量级**做容量规划；这是范围待 M0 冻结的估算，不是六类任务全部训练达标的工期承诺。明确必选方向、训练/推理要求、后端与重复次数后必须重估。不含未确定的资源采购/审批、外部依赖阻塞和长时训练等待；单人+Agent 不直接套用两名研发的历时。不能为满足排期降低门槛或事后缩减验收集。

首轮只安排 M0：

1. 保护当前工作树，重新测当前基线，不动用户任务与数据。
2. 确认 D01–D05；完成动作权限和对象/schema 对照评审。
3. 明确一个实际可用 Worker 目标、CPU 开发路径和 GPU 验证分支。
4. 冻结首个开放工程任务与首个可信改进任务，准备合法开发数据；留出集另管。
5. 产出可执行 M1 工作单、测试命令和证据路径，再开始代码实施。

## 7. 风险、降级与发布门

| 风险 | 处理方式 | 不能采用的捷径 |
| --- | --- | --- |
| 自主修复政策未批准 | 维持旧规则；明确辅助工程路径及人工成本 | 把“同意产品方向”当允许生成/执行任何补丁 |
| 隔离/GPU 后端不可用 | 记录真实阻塞；等待指定资源或单独批准替代环境 | 在宿主直接跑第三方脚本、伪称 GPU 可用 |
| 动态评测器不可信 | 独立校准、冻结实现、权限隔离、结果复验 | 让训练 Agent 自写评分再自我放行 |
| 主观任务评测资源不足 | 先明确评价协议与人力，限制对外声明 | 用单一代理指标代替用户业务效果 |
| 新路径损伤既有任务 | 功能开关、可回滚迁移、旧任务回归；只追加历史 | 删旧 Run、重写旧合同或把旧成功当新结果 |
| 经验无收益/泄漏 | 不发布优势声明；撤销不可信经验，隔离与重测 | 挑选成功案例或把终测答案喂回经验库 |
| 不确定状态导致重复执行 | 服务端幂等、租约对账和人工处置未知作业 | 刷新页面就再次训练、重复消耗授权 |

新能力可通过服务端功能开关逐步启用，关闭后保留历史证据并阻止新动态执行。schema 迁移必须可备份和验证；不兼容记录只读降级，不猜测成有效当前结果。回滚不得删除构建/运行/批准记录。

发布证据分开登记：单元/集成 → 真实 Worker → 关键 PC 旅程 → 留出与优势对照 → 干净安装/消费 → 用户验收 → Git commit/push → CI → Tag/Release。只有得到对应授权并核验精确提交，才能声明外部发布；本地可运行不等于生产部署。

每阶段交付报告必须包含：完成工作包、实际代码与 schema 变更、权限变化、测试与真实旅程证据、业务效果、未通过项、资源/人工消耗、当前允许对外声明的能力、下一阶段前置条件。方案中的勾选、截图或 Agent 文字不替代这些证据。
