## 一句话定位

以通用编程 Agent 的模型工程能力为底座，在用户的数据、资源和时间约束内，通过可信评测、证据驱动实验和持续改进，交付可验证的模型业务效果。

“通用”是任务类型开放，不要求研发提前为每个场景开发插件；“专业”是更可信、更省试错、持续积累有效经验。两者必须同时成立。

## 路线概览

| 阶段 | 用户能得到什么 | 主要证明 |
| --- | --- | --- |
| M0 基线与决策 | 明确要做什么、允许如何做、怎样判定完成 | 范围、权限、评测基准与对象协议经过确认 |
| M1 可靠执行与 PC 控制 | 看得懂、停得下、刷新后找得回 | 隔离、可终止任务、对话审批与状态闭环 |
| M2 开放模型工程 | 未预装方案的任务也能完成真实适配和训练 | Agent 构建、真实资格验证、批准注册、训练与交付 |
| M3 可信改进 | 提交错误样本后得到有证据的改进结果 | 业务切片、对照实验、独立验收和退化检查 |
| M4 经验与跨任务验证 | 相似任务更少走弯路，新类型不依赖主干补丁 | 跨模态验证、经验检索适用性和收益消融 |
