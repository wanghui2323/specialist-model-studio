## D01：动态编码与有界自主修复

现状：第三方执行必须隔离；现行规则明确禁止 Agent 自主生成 repair patches，通用可执行构建尚未交付。

建议目标：允许 Agent 在任务隔离目录内生成适配/训练代码，并在事先批准的文件、网络、资源、时间和次数范围内生成及验证修复。新增尝试保留父 attempt、完整差异、输入/环境摘要和证据。

边界不变：不能修改验收门、终测策略、授权范围和执行隔离；不能执行宿主命令作为绕行；不能修改产品控制平面；范围扩大重新审批。动态注册仍需人批准精确资格证据摘要。

需确认：是否批准上述模式，以及默认预算的设定方式。若只选择逐补丁人审，也可交付辅助工程路径，但不能宣称“自主修复”已验收。

生效条件：产品负责人明确确认 → 版本化策略与 `AGENTS.md` 修订审查 → 服务端与 Worker 拒绝/撤销测试 → 再开放工具。此链未完成前不生成自主修复补丁。

## D02：首个执行后端与加速器范围

2026-09-11 用户批准记录：对“是否允许先在本机安装隔离容器环境，用 CPU 验证外部模型执行？自主修复权限仍单独审批”回答“可以”；随后补充“如果本机资源不够，也可以用火山引擎服务器”。

生效范围：可安装本机隔离容器运行时，并进行有资源上限的 CPU 可行性验证。火山引擎是资源不足时可采用的后备执行环境；是否已有实例、访问方式、实例规格尚未提供。不能从该补充推导新建付费实例、无限费用或用户数据外发许可；实际启用云端前确认这些事实。D01 不随本次回答获批。

本轮默认实施细节：独立用户级运行时目录和命名实例，不切换全局 Docker context、不挂载用户 HOME 或转发 SSH agent；先做小型验证并在结束后释放 VM 内存。不把运行时安装成功计为产品通用执行链完成。

建议：先以可验证 OCI CPU 后端打通协议，并在 M0 同时确定需要验证的 GPU 目标，而非把跨模态训练永久限制在 CPU。GPU 后端资格独立验证。

尚需确认的云端范围：火山引擎是否已有实例、CPU/GPU 与内存规格、SSH 配置别名、存储/下载/执行预算和访问方式。优先复用已有合适实例；若需要新建付费实例，先确认规格、价格、最长运行时间和关闭方式。没有资源清单时不假定已有 CUDA Worker、可用 MPS 隔离后端或云账户。云端仍需相同的源/环境摘要、隔离、资源限额、终止、证据与批准协议，不能因换机器跳过资格验证。

不允许：用宿主 GPU 探测代替容器/Worker 内训练证明；自行租机、购买算力或把用户数据发到外部机器。若环境缺失，相关里程碑标记阻塞，不改成假训练或偷偷缩减已冻结验收集。

## D03：首轮任务与业务验收

建议：开发阶段采用一个未预装 NER 工程任务证明开放执行，采用现有整图分类任务证明错例改进；后续覆盖 NER/ASR/OCR/TTS 等跨任务验证。具体仓库、版本、合法数据与预算在 M0 固定，不在方案中虚构。

需确认：首轮输入输出、可接受的模型效果、延迟、资源边界；TTS 等需要的人工评价方式。各项均属新任务合同，不复用或降低旧任务门槛。

分类样例不是任务白名单；仅用它降低首轮差异化验证的工程变量。最终通用性必须包含未预注册的留出任务。

## D04：优势目标与验证成本

建议：对照同底模、同数据/工具/资源权限的通用工程 Agent；比较独立达标率、人工介入、总成本、时间和错误放行；经验库另做消融。

分两次确认：M0 冻结基线运行预算、指标定义、重复次数、必选任务和业务重要性；M2 具备执行条件后运行开发基线，在正式优势对照/留出评测前冻结质量/效率提升阈值。不要求 M0 先完成依赖 M2 的训练对照。具体训练任务的业务门在训练前独立确认，不因这个顺序而延迟或放宽。

没有批准目标或有效对照时，只能说“机制已实现”，不能宣传“优于通用 Agent”。

## D05：经验复用与数据范围

建议：默认 task/workspace 私有；优先沉淀不含用户原始数据的环境兼容性和受证据支持的工程经验。

需确认：跨任务可复用的摘要范围与撤销规则。跨客户、外部服务上传、私有权重共享不在默认授权内。终测数据、答案和可反推验收题目的记录不进入优化经验库。
