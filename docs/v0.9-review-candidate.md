# Specialist Model Studio v0.9 RC 审核指南

这是 `0.9.0rc1` 的未发布审核入口。它用于体验 V1–V3 的 analysis-only 产品路径，不是完整 BYOM 训练或生产发布声明。

## 15 分钟审核路径

1. 启动本地服务：

   ```bash
   uv sync --extra server --extra test
   uv run specialist-model-studio serve --runs-dir runs --host 127.0.0.1 --port 8765
   ```

2. 打开 <http://127.0.0.1:8765/app>，输入一句信息不足的需求，例如“我想训练一个语音模型”。预期系统先通过可选项澄清任务类型，不应立即伪造训练步骤。
3. 新建一个“文档图片分类”任务，确认任务规格，然后搜索并人工选择一个公开 GitHub 训练仓库。
4. 在右侧工作区依次查看不可变 commit、manifest、静态分析、训练计划和审批 digest。
5. 执行资源检查。当本机没有已验证隔离运行时时，预期结果是带 detector、事实和恢复动作的 `blocked_environment`，不是训练成功。
6. 刷新页面并从左侧任务列表重新打开。任务、来源、分析、计划和 blocker 应继续使用同一组 ID/digest，不应重放写请求。

## 评审时应区分的三类结论

| 结论 | 当前状态 | 含义 |
| --- | --- | --- |
| V1–V3 实现候选 | 已完成 | 可体验真实来源、分析、计划和资源阻断 |
| L1/L2 `verified` | 未完成 | 尚无 C01–C07/C15 各自全部 6/6 的正式证据包 |
| 完整 BYOM / GitHub Release | 未完成 | L3–L5、PR 合并、Tag 和 Release 仍是后续独立门禁 |

## 快速真值检查

```bash
git status --short --branch
git rev-parse HEAD
uv run specialist-model-studio --version
curl -fsS http://127.0.0.1:8765/health
curl -fsS http://127.0.0.1:8765/runtime
```

`/health` 应显示 `release_status=unreleased_rc`。`/runtime` 应明确显示当前通用协议终止在 `resource_feasibility`，且未验证隔离运行时时 `byom_execution_available=false`。
