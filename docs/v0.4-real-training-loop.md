# v0.4：用户图片训练闭环

## 这一版解决的问题

v0.3虽然会真实调用scikit-learn训练模型，但浏览器只提供固定数字识别按钮，并把短时间内产生的状态事件显示成多轮聊天，容易让用户误认为它在播放预制剧情。

v0.4把主对象从“孤立运行”提升为“训练任务”。训练任务持有稳定 `task_id`、数据集版本、数据体检报告、人工确认的任务合同和运行谱系。前端不再用聊天气泡呈现运行日志，也不人为延长训练时间。

## 已实现的真实闭环

```text
创建训练任务
  ↓
上传 class/image.jpg 结构的 ZIP
  ↓
安全解压 + 图片解码 + 类别/数量/坏图/重复/标签冲突体检
  ↓
编辑验收门槛和图片尺寸
  ↓
确认数据授权、标签含义和离线门槛
  ↓
比较4个CPU候选模型 → 验证集选择 → 独立测试
  ↓
失败样本 + 指标 + 模型 + 模型卡 + 学习报告 + 哈希清单
  ↓
人工批准优化策略 → 创建带 parent_run_id 的子运行
```

未完成三项人工确认时，后端拒绝启动训练。修改数据或合同会撤销旧确认；旧运行仍保留在任务的 `run_ids` 中，但不会冒充新数据的当前结果。

## 数据安全边界

- 服务默认只监听 `127.0.0.1`；上传数据保存在 `runs/_workspace`，不会进入Git；
- ZIP原始大小上限200MB，解压后图片上限750MB、10,000张；
- 拒绝绝对路径、`..` 路径穿越、少于2类、每类少于5张和跨类别重复图片；
- 同标签重复图片会在划分前去重，无法解码、去重和类别不均衡都会写入数据报告；
- Joblib模型只应在哈希匹配且来源可信时加载。

## 当前模型能力

`image-folder-classification` 使用Pillow把图片转换为固定尺寸RGB和梯度特征，在CPU上比较：

- most-frequent baseline；
- logistic regression；
- linear SVC；
- random forest。

它适合验证“用户数据是否足以训练一个轻量分类模型”，不等于完整OCR、目标检测、工业视觉平台或生产推理服务。文件级随机划分也不能证明跨人员、设备、时间和现场泛化。

## 接口对象

- `POST /tasks`：创建任务草稿；
- `POST /tasks/{task_id}/dataset`：上传并体检ZIP；
- `PATCH /tasks/{task_id}/contract`：修改门槛与Recipe参数；
- `POST /tasks/{task_id}/confirm`：确认授权、标签和门槛；
- `POST /tasks/{task_id}/runs`：启动冻结合同对应的运行；
- `GET /runs/{run_id}/events/stream`：读取真实SSE事件；
- `GET /runs/{run_id}/artifacts/{name}`：下载制品；
- `POST /tasks/{task_id}/runs/{run_id}/strategies/{strategy_id}/apply`：明确批准后创建子运行。

## 本轮验收

- 19个Python单元/端到端测试和2个DSH Node契约测试；
- 浏览器完成任务创建、ZIP上传、数据体检、未确认阻断、合同冻结、真实训练、制品展示；
- 策略取消不创建子运行，明确批准后创建新 `run_id` 并保留 `parent_run_id`；
- 桌面与390px移动视口可用，浏览器控制台无警告或错误。

这些证据只证明本地Alpha闭环。多用户鉴权、远程计算隔离、GPU调度、真实OCR/检测/语音Recipe、生产影子测试和部署仍是后续范围。
