# v1.0 Source Release Candidate

`Specialist Model Studio 1.0.0rc1` is the first candidate that treats the
conversation, native specialist agents, training engine and evidence workspace
as one product.

## Distribution decision

This candidate is distributed from a source checkout. The complete `start`
path depends on repository-owned DSH adapter, preset and launcher files. The
Python wheel is intentionally backend-only until those assets have one
package-aware installation path.

The boundary is fail-closed:

- `specialist-model-studio start` requires the source checkout and refuses an
  installation that lacks the launcher;
- `specialist-model-studio serve` remains the backend-only developer command;
- a healthy backend is not reported as a connected AI team;
- a source or model search result is not reported as a trained model;
- an unregistered capability must end in typed blocker evidence, with no fake
  run or timer-driven progress.

## Reviewed startup

```bash
git clone https://github.com/wanghui2323/specialist-model-studio.git
cd specialist-model-studio
git checkout <exact-40-character-candidate-commit>
uv sync --frozen --extra server --extra test
npm ci --prefix integrations/deepseek-harness --ignore-scripts
npm ci --prefix acceptance/dsh-runtime --ignore-scripts
export DEEPSEEK_API_KEY="<your-key>"
uv run specialist-model-studio start
```

A source RC uses only the repository-local
`acceptance/dsh-runtime/node_modules/.bin/dsh`. Its direct dependency and full
transitive graph are committed in `package.json` and `package-lock.json`, with
the CLI fixed to `0.1.0-rc.6`; a global `dsh` executable is not release
evidence. DSH state defaults to the selected runs directory at `runs/.dsh`, so
a detached cold clone does not silently reuse the developer's `~/.dsh` profile.
`DSH_HOME` may select another isolated directory explicitly.

A successful command prints only the Studio `/app` URL. `/runtime` must bind
the exact source root, 40-character source revision, source-dirty state, runs
directory, workspace, DSH origin, conversation schema `2.0`, projector `3.2`,
action schema `1.0` and synthesis verdict `1.0`. A public RC acceptance run
must report `source_dirty: false`. The direct launcher exposes
`MODEL_HARNESS_ALLOW_SYSTEM_DSH=1` only as a local development escape hatch;
public starts and runs marked `SPECIALIST_MODEL_STUDIO_L6_ACCEPTANCE=1` refuse
that fallback when the locked local CLI is absent.

## Acceptance journeys

The candidate is not public-release ready until the same remote detached clone
passes both journeys on desktop and 390 px mobile:

1. A real CSV house-price task: clarify continuous prediction, import data,
   confirm the exact contract, approve a real run, then inspect evaluation and
   artifact evidence.
2. An unregistered speech or vision task: clarify the goal, resolve an immutable
   public source, produce static analysis and typed blocker evidence, and prove
   that no training run was created.

Both journeys must also pass stop/recovery, refresh, task-list re-entry, service
restart, AI-turn ownership, one-authoritative-state and exact ObjectRef checks.

## Release truth

The machine-readable contract is
[`acceptance/v1.0-gates.json`](../acceptance/v1.0-gates.json). Local tests,
screenshots or a version number do not prove a remote push, CI, cold clone, tag
or GitHub Prerelease. Evidence uses only `passed`, `failed` or `blocked`; it
never aggregates `skipped` into success.
