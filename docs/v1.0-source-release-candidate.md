Python/API/插件分别为 `1.0.0rc2` / `1.0.0-rc.2` / `1.0.0-rc.2`。完整产品从源码启动，wheel 是 backend-only。它不宣称生产就绪、远程 GPU、所有模型服务已实测或完全自主环境构建。

## 冻结安装

```bash
git clone https://github.com/wanghui2323/specialist-model-studio.git
cd specialist-model-studio
git checkout <exact-40-character-candidate-commit>
uv sync --frozen --extra server --extra test
npm ci --prefix integrations/deepseek-harness --ignore-scripts
npm ci --prefix acceptance/dsh-runtime --ignore-scripts
```

使用 Python 3.12 和 Node.js 24 LTS。仓库锁定 DSH CLI `0.1.0-rc.6`，不以全局 CLI 或开发者已有 `.dsh` profile 作为冷启动证据。默认 profile 保存在所选 runs 目录的 `.dsh` 中。

## CPU worker

先安装并启动 Docker 兼容 Linux 服务。Linux Docker Engine 可直接使用。macOS 可用 Docker Desktop，或使用已安装的 Colima。Colima 场景必须给 VM 显式共享隔离作业目录，例如：

```bash
mkdir -p "$HOME/.local/share/specialist-model-studio/isolated-jobs"
colima start --profile specialist-model-studio --runtime docker --cpu 3 --memory 5 \
  --mount "$HOME/.local/share/specialist-model-studio/isolated-jobs:w"
export DOCKER_CONTEXT=colima-specialist-model-studio
```

不要通过删除既有 VM、放宽文件访问或共享整个主目录来恢复现有任务。已有 Docker/Colima 配置可继续使用，只需保证所选目录实际可挂载。

```bash
uv run python scripts/prepare_cpu_worker.py --configure
```

脚本验证仓库保存的官方 Python manifest 摘要和基础文件系统，下载逐包 SHA-256 锁定的公开 wheel，再在完全断网的构建阶段安装。完成后用断网、只读、无特权容器检查包导入与张量梯度。构建上下文只包含已审阅 recipe 和已校验依赖 wheel，无用户数据、模型权重、源码工作区或凭据。

Docker VM 访问 CDN 不稳定时，准备器可在宿主下载并校验官方镜像 blob，通过 `docker load` 加载；不在宿主解包或执行镜像代码。Docker 重编码 OCI 配置时，必须匹配官方文件系统 diff ID 和执行配置，并记录实际本机 image ID，不制造相同摘要。

依赖准备阶段只下载 wheel 和公开镜像数据，不执行模型代码；构建与真实任务阶段由 OCIExecutor 默认断网、限制 CPU/RAM/PID/时间、只挂载阶段允许的文件。构建成功输出 image ID 和本机回执；不同构建/架构不能仅凭依赖版本推定相同 image ID。任务必须绑定其实际使用的不可变镜像。

`--configure` 仅创建新的 operator 配置，拒绝默默覆盖。已有配置时可选择输出 image ID 的环境覆盖：

```bash
export MODEL_HARNESS_EXECUTION_IMAGE=sha256:<actual-built-image-id>
export MODEL_HARNESS_ISOLATED_ROOT="$HOME/.local/share/specialist-model-studio/isolated-jobs"
```

## 协调模型服务

已实测路由为 Codex CLI `0.145.0` 的既有 ChatGPT 登录，模型 `gpt-5.6-sol`：

```bash
codex login status
export MODEL_HARNESS_AGENT_PROVIDER=codex-cli
export MODEL_HARNESS_AGENT_MODEL=gpt-5.6-sol
uv run specialist-model-studio start
```

CLI 只提供推理与动态工具请求；DSH 管理角色、对话、工具和本次审批。生成代码仍只进入隔离 worker。其 history-injection/dynamic-tool API 属实验接口，必须实际验证兼容性。

API 或本地服务也可通过已安装的 DSH provider adapter 配置。DeepSeek 可在本机设置 `DEEPSEEK_API_KEY`；其他路由用对应的 Models 设置和本地凭据配置。不能从服务配置存在推定真实调用通过；不能用 mock 回复或材料检查代替 Agent 训练链。

## 冷克隆与发布证据

候选提交必须 clean，安装目录、运行目录和 profile 必须是新的。`/runtime` 应报告准确 source root/revision、source_dirty、runs、workspace、origin、schema 与 provider。共享已有 Codex 登录可以用于真实模型调用；不得复用旧任务、旧 profile、训练数据/模型缓存来冒充新流程。

两个旅程必须通过真实页面：

1. 已注册基线：新材料、数据版本、确认、真实训练、独立评估、新输入、下载与重载。
2. 无预设 domain Recipe：Agent 生成实现、隔离资格验证、实际 Run、独立评估、新输入、下载与重载；仅阻断不算通过。

还需检查停止落实、刷新、任务切换、服务重启状态、历史批准不重放、完成产物保留和 PC 三种宽度。模型效果失败与下一步必须可理解，不能改门槛或把测试曝光后调优的结果当独立准出。

使用 [v1.0-gates.json](../acceptance/v1.0-gates.json) 和 `scripts/verify_v10_rc.py` 汇总原始证据。远端 exact-commit detached clone、CI、Tag 与 GitHub Prerelease 分别取得回执；本地通过不自动表示已经发布。复验中产生的原始数据、声音、权重与私人日志不上传。

历史 rc.1 的“未知任务诚实阻断”门槛已归档，不能代替当前通用 Agent 验收。
