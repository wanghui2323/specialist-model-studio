# v0.2 Plugin Runtime and Chat Adapter Boundary

## Why this shape

The frontend should be replaceable without changing training semantics. AI PM Model Harness therefore owns contracts, runs, events and artifacts; a chat framework only translates user intent into API calls and renders the resulting events.

The design borrows four ideas from [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness):

1. capabilities live behind plugins instead of a central list of hard-coded branches;
2. side effects have explicit seams and can be reviewed or cancelled;
3. long-running work emits events instead of blocking a chat turn;
4. UI cards are views of canonical state, not the source of truth.

DeepSeek Harness is currently described by its repository as a developer preview. Its TypeScript runtime is therefore not imported into this Python core. The first integration should be a thin tool/conversation-node adapter over HTTP and SSE.

## Runtime ownership

```text
DeepSeek Harness / another chat UI
        │ tool calls + SSE
        ▼
HTTP adapter (model_harness.server)
        │
        ▼
RunService ── cancellation / recovery / child runs
        │
        ├── RunState + events.ndjson
        ├── PluginRegistry
        └── RecipePlugin
              ├── validate_contract
              ├── train / evaluate / package
              ├── propose_strategies
              ├── apply_strategy
              └── deep_verify
```

The canonical objects are JSON task contracts, `run_state.json`, `events.ndjson`, artifact files and `run_manifest.json`. A conversation transcript may point to these objects but must not replace them.

## Run lifecycle

Normal execution uses:

```text
created → queued → preflight → training → evaluating
        → proposing → packaging → completed
```

Alternative terminal states are `cancelled`, `failed` and `interrupted`. `needs_input` is reserved for plugins that can identify a missing human decision before training.

Cancellation is cooperative. A request is persisted immediately, then honored at the next safe stage boundary. A service restart never silently continues an in-flight run: the old run becomes `interrupted`, and resume creates a child run from its frozen contract.

## HTTP tools for the first chat adapter

| User intent | HTTP operation | Suggested UI result |
| --- | --- | --- |
| “有哪些训练能力？” | `GET /recipes` | Recipe cards |
| “开始训练” | `POST /runs` | Task card with run id |
| “现在到哪了？” | `GET /runs/{id}` | Current stage and gate state |
| Live progress | `GET /runs/{id}/events/stream` | Timeline from SSE events |
| “先停下” | `POST /runs/{id}/cancel` | Cancellation requested notice |
| “刚才中断了，继续” | `POST /runs/{id}/resume` | New child-run card |
| “下一轮怎么优化？” | `GET /runs/{id}/strategies` | Strategy approval cards |
| “批准位移增强” | `POST /runs/{id}/strategies/{strategy}/apply` | New child-run card |

The adapter should render strategy cards with hypothesis, evidence, expected effect, cost and risk. It must require explicit confirmation when `requires_approval` is true and reject strategies where `actionable` is false.

## Event contract

Every event contains:

```json
{
  "schema_version": "0.2",
  "event_id": "uuid",
  "seq": 8,
  "timestamp_utc": "ISO-8601",
  "run_id": "...",
  "task_id": "...",
  "type": "optimization.strategies_proposed",
  "stage": "proposing",
  "plugin_id": "digit-classification",
  "payload": {}
}
```

Consumers should order by `seq`, persist the last seen sequence and reconnect with `after_seq`. Event payloads are display inputs; current truth remains `run_state.json` and the frozen artifacts.

## Plugin compatibility rule

Core code may depend on `RecipePlugin`; it must not import a concrete Recipe. A Recipe may use AutoML, a fixed open-source model, a local training script or a remote worker, provided it preserves the contract and artifact rules. Frontend adapters may depend on the HTTP schema; they must not read plugin-private Python objects.

This boundary lets later integrations reuse existing tools such as FLAML, AutoGluon or MLflow without turning the Harness into another AutoML framework.

## Not yet implemented

- DeepSeek Harness tool and conversation-node package;
- authentication, multi-user isolation and remote workers;
- automatic resume within an incomplete training stage;
- arbitrary Agent-generated training code sandbox;
- OCR, audio and industrial-CV production Recipes.

These omissions are deliberate alpha boundaries, not completed capabilities.
