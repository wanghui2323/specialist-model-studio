# v0.1.0 Release Verification

核对日期：2026-08-20

- 已形成可独立版本控制的公开项目结构，项目许可证为MIT；
- 已实现一个端到端参考Recipe：8×8手写数字分类；
- 已完成项目测试、Skill结构校验、真实Skill运行和深度产物验证；
- 本报告覆盖首个GitHub公开版本的本地发布前验证，不宣称生产可用。

## 已验证的参考运行

测试环境为Apple Silicon、16GB统一内存、CPU执行。固定随机种子为42。

| 检查项 | 结果 |
| --- | ---: |
| 候选模型 | 4个 |
| 胜出模型 | RBF SVM |
| Clean Accuracy | 0.9806 |
| Clean Macro-F1 | 0.9805 |
| Worst-class Recall | 0.9429 |
| 模型大小 | 0.1195 MB |
| 单样本本地p95延迟 | 约0.14 ms |
| 离线门槛 | 全部通过 |
| 深度产物验证 | 通过，6个核心制品 |

压力测试揭示了明显脆弱性：加入强高斯噪声后的Accuracy约为0.1028，右移一个像素后约为0.3167。这正是Harness保留诊断切片的原因：干净测试集高分不能替代真实业务数据验证。

## 已知问题与发布前事项

- 当前测试依赖组合会显示两条来自scikit-learn/Joblib与NumPy 2.5形状赋值相关的弃用警告，不影响本次测试结果，但正式发布前应在干净环境复测并收紧兼容版本；
- Digits只是教学数据，不代表合同、票据、相机、工业零件或真实设备分布；
- 当前只有一个Recipe，尚未证明Harness能跨OCR、语音、CV和预测任务复用；
- 后续每次GitHub发布前仍需在准备提交的文件集合上重新做许可证和隐私扫描。

## 下一验证目标

第二个Recipe应选择真实图片文件夹输入的轻量图像分类任务，用来验证：当数据不再由框架内置时，Harness能否正确提出数据需求、生成数据报告、冻结发布集，并继续产出同一种运行合同和学习报告。
