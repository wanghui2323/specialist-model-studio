# v0.5：对话式模型训练Harness

## 产品结论

这轮不再维护一个“看起来像Agent”的自制聊天页面。DeepSeek Harness Web承担主对话体验，Model Harness提供模型训练领域工具和唯一事实源，原来的 `/app` 收敛为训练证据工作台。新会话默认使用项目提供的“模型训练模式”，而不是通用编码模式。

用户可以像使用Genspark或Manus一样先说目标，再由Agent逐步索取必要信息、调用工具、展示结果并请求批准；区别在于它代办的是小模型训练任务，而不是通用搜索或办公任务。

## 所有权边界

```text
DeepSeek Harness
  持久会话 / 模型路由 / Agent循环 / 工具卡片 / 原生审批
                    │ model_harness_* 工具
                    ▼
Model Harness Python后端
  任务 / 数据集 / 体检报告 / 冻结合同 / 运行 / 事件 / 指标 / 制品 / 谱系
                    │ 同一 task_id
                    ▼
/app 训练证据工作台
  只读取和操作后端事实，不保存另一套聊天或运行状态
```

这是插件适配，不是fork。我们没有复制或改造DeepSeek Harness核心代码；插件通过工具注册表增加模型训练能力，通过系统提示增加领域操作规则，并通过官方agent preset机制提供聚焦的模型训练会话。该preset不暴露通用Shell和文件编辑工具。训练后端即使不启动DSH也可以独立测试和运行。

DSH已经保存过的用户默认设置优先于bundle默认值，因此升级后的老profile可能仍显示“标准模式”。在设置中的Agent预设切换一次“模型训练模式”即可影响后续新会话；已有会话继续使用创建时的preset，不会被偷偷换工具集。

DeepSeek Harness官方将自身描述为基于Cordis的插件优先系统，模型、工具、会话和Agent循环都由插件组合；会话日志可重建状态，工具执行可接入审批与后台任务。这些机制正好适合训练任务的长流程与人工门槛：

- [DeepSeek Harness repository](https://github.com/deepseek-ai/deepseek-harness)
- [Architecture](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.md)
- [Web user guide](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/user/guide/index.md)

## 一次真实对话如何运行

1. Agent先调用 `model_harness_list_tasks`，避免重复创建。
2. 用户描述清楚目标后，Agent创建持久任务草稿。
3. Agent向用户索取明确的本地ZIP路径；导入属于数据变更，会出现DSH原生审批。
4. 后端检查目录、解码、数量、重复和标签冲突；Agent解释报告，不编造结论。
5. 用户审查标签和门槛，后端记录三项明确确认。
6. 启动真实运行前再次经过DSH审批；后端也校验任务是否确实就绪。
7. Agent读取版本化事件和最终结果，区分排队、运行、完成与失败。
8. Agent返回同一任务的 `workbench_url`。工作台展示合同、指标、失败样本、制品哈希和父子运行。
9. 优化建议只是建议；批准指定策略后，后端创建子运行并保留父运行。

## 双重防线

DSH审批和后端校验解决不同问题：

- DSH审批回答“用户是否允许Agent现在执行这次变更”；
- 后端校验回答“任务是否具备数据、确认和状态前置条件”。

即使模型误调用工具，拒绝审批不会修改训练状态；即使绕过UI直接请求API，后端仍会拒绝缺少确认或非法状态的运行。

## 当前能力边界

- 用户数据Recipe目前只支持多类别图片分类，不等于OCR、目标检测或工业视觉全平台；
- DeepSeek Harness目前仍是developer preview，升级后需要重跑插件契约与浏览器闭环；
- 当前是本机单用户Alpha，没有远程多租户鉴权、云GPU隔离和生产发布审批；
- 对话可以代办训练流程，但不会自动决定数据许可、标签语义、验收门槛、成本扩张和上线。
