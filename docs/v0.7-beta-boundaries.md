# v0.7 Beta 能力与边界

## 版本和发布语义

- Python 版本：`0.7.0b1`
- 产品标识：`v0.7.0-beta.1`
- 当前结论：本地 Beta，不是生产发布
- GitHub 结论：本地代码、测试或文档不能证明已 push/tag/release；只能由远程 commit、tag 和 Release 证据建立

## L4 证据对象

1. `EvaluationReport` 从已完成 Run 和哈希绑定制品得出分层结论。
2. `SampleInference` 对用户显式提供的新样本做格式/体积/来源检查，复用 Recipe 预处理。
3. `InferenceCheck` 重新验证模型哈希，真实 `joblib.load + predict`，记录输入/输出哈希与耗时。
4. `ArtifactBundleBuilder` 只收集允许交付的文件和当前证据，生成可下载 ZIP。

这些对象都属于某个 Run；HTTP 入口还会同时校验 `task.run_ids` 和 `run_state.task_id`，防止跨任务读写证据。失败的样本检查可查询，但不会创建 Run 或改变父子谱系。

## 真实验收

### Hugging Face 端到端场景

```bash
.venv/bin/python scripts/run_hf_real_scenario.py
```

这是联网命令，会下载公开固定 commit 资产。它验证的是官方 HF 资产→CPU ONNX 特征→图片训练→评测→新样本→Bundle→重启查询，不是联网下载任意模型并自动微调。

### L0–L5 门槛聚合

```bash
.venv/bin/python scripts/verify_v07_beta.py \
  --user-approval-checkpoint-id "<user-confirmed-checkpoint-id>" \
  --output runs/acceptance/manual-v07/acceptance-report.json
```

`verify_v07_beta.py` 会按 `acceptance/v0.7-gates.json` 聚合证据。它不允许 `skipped`，也不接受手写外部证据。每轮由随机 challenge 绑定受控 producer，实际执行固定 HF 训练、双视口 Chrome、两个真实服务 PID 和 `--no-local` 冷克隆；聚合器再独立复核 schema、producer 源哈希、制品 SHA-256、Console/Network、实时对象所有权和 Bundle 下载。任一依赖、原始证据或 live 查询缺失都会 fail-closed。GitHub 发布链另由 `gh api` 查询，不影响已经独立得出的本地 Beta 结论。

## 尚未内置

- OCR 文字检测/识别；
- 目标检测、分割、姿态或工业异常检测；
- ASR、TTS、声纹、流式唤醒词运行时；
- 时序预测、表格分类和其他预测家族；
- 文本分类、序列标注、嵌入或生成模型训练；
- 任意 Hugging Face 架构微调；
- 可自动执行生成 Python 的隔离 Recipe 构建环境；
- 云 GPU 调度、多用户鉴权、生产影子测试和部署。

这些任务可以被 TaskSpec 表达，但在有可验证 Recipe/Data Adapter 之前只能停在能力缺口，不能被宣称为“已支持”。
