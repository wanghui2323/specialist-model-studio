# v0.3：对话控制台与DeepSeek Harness适配

## 这一轮闭合的任务

用户可以在浏览器中用一句“开始数字识别实验”创建运行，查看版本化阶段事件、独立测试指标和证据关联的优化策略。策略不会自动执行；用户在审批对话框明确确认后，系统创建新的子运行，并保留父运行的合同、模型与证据。

刷新页面后，控制台从运行目录和事件流重建视图。普通聊天文本本身暂不持久化，运行与审批事件才是事实源。

## 架构边界

```text
独立Console ─┐
             ├─ HTTP API → RunService → Recipe插件 → 运行制品
DSH工具插件 ─┘                  ↓
                            版本化事件与父子谱系
```

- `model_harness/web` 是零外部前端依赖的本地控制台；
- `model_harness/chat.py` 是确定性命令层，不冒充通用LLM；
- `integrations/deepseek-harness` 是profile bundle和薄HTTP客户端，不复制或修改DeepSeek Harness源码；
- Python后端是唯一状态与审批事实源，两种前端不会各自维护一套训练状态。

## 当前验证层级

本版本已经验证：

- Python端15个单元/端到端测试；
- DSH适配器2个Node契约测试；
- 桌面与390px浏览器中的启动、进度、策略取消、明确批准、子运行和刷新回看；
- DeepSeek Harness `0.1.0-rc.6` profile成功加载bundle，插件页显示“已挂载、已启用”；
- DSH模型真实调用 `model_harness_list_recipes`，Model Harness收到 `/recipes` 请求并返回结果。

这些证据不等于生产就绪。当前没有多用户鉴权、远程隔离、真实OCR/语音/CV数据管道，也没有跨设备对话历史。

## 人工批准规则

“建议”与“批准”是两个状态。无论从独立Console、HTTP API还是DSH调用，策略执行都必须带明确批准；执行结果总是新的子运行，不能覆盖父运行。真实数据授权、许可、成本扩张和生产发布仍由人决定。
